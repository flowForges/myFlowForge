# myFlowForge

**AI コーディングエージェントのための macOS コックピット。**

**Claude Code、Codex、Cursor、Gemini、qoder、opencode、Trae** をはじめとするコーディング CLI をひとつの macOS デスクトップに集約 —— **会話の途中でエージェントもモデルも切り替え**、**複数プロジェクトを並行して開発**し、**軽量ワークフロー（マニュアル操作）** で一歩ずつ手綱を握り、ステージの合間に自分の **Hook** を差し込めます。

## myFlowForge とは

AI コーディング CLI はどれも自分専用のターミナルに閉じこもっていて、セッション状態もクォータも別々、お互いの存在すら知りません。ひとつ選んだら、そのタスクが終わるまで付き合うしかない。

**myFlowForge はそれらをひとつ屋根の下に集めます。** エージェントとモデルは *1 ターンごと* のプロパティであって、セッションのものではありません。Claude Opus で設計を練り、実装は Codex に渡し、後片付けは安いモデルへ —— すべて同じ会話のなかで、コンテキストを保ったまま。

その上に載るのが**軽量ワークフロー**です。勝手に走り出すベルトコンベアではなく、同じ会話に薄い構造を一枚かぶせるだけ。どのステージも、あなたが「次へ」を押すまで待ちます。

> ⚠️ **プロジェクトの状態：** 開発が続いている個人プロジェクトです。対象は **macOS**（Apple Silicon および Intel）。Electron ベースなのでソースから他プラットフォーム向けにビルドすることは可能ですが、現在パッケージを配布しているのは macOS のみです。現在の安定版は **1.1.0** です。安定版のあいだに出る beta が新機能の先行投入先になります。

## ✨ 本当に大事な 5 つのこと

### 1. お気に入りを 1 つ選ぶのではなく、まとめて使う

12 のコーディング CLI がひとつの画面に共存します：**Claude Code · Codex · Cursor · Gemini · qoder · opencode · Qwen · Copilot · Pi · Kimi · Reasonix · Trae**。

モデル一覧は**各 CLI のローカル設定から実際に読み出し**ます。ハードコードは一切なし —— 画面に出るものは、あなたのアカウントで本当に動くものだけ。手動で項目を足すこともでき、次回の更新で消えたりしません。**opencode** はそれ自体がマルチベンダーのゲートウェイなので、1 つ繋げば一気に広がります。

### 2. ひとつのセッションの中でエージェントとモデルを切り替える

入力欄の下には常にエージェント・モデル・権限モードの 3 つのセレクタが並んでいます。次のメッセージを送る前ならいつでも変更できます。

- あるモデルが詰まった・的外れになった → 切り替えてそのまま続ける。これまでの会話は見えています。
- あるプロバイダのクォータが切れた → 別のプロバイダへ、同じセッションのまま。
- 考えるのは高いモデル、力仕事は安いモデル。

ネイティブ再開に対応するエージェント（Claude Code、Codex、Cursor、qoder、opencode）は自身のセッション履歴をそのまま継続します。それ以外は myFlowForge がコンテキストを再構成します。どちらでも、あなたは話し続けるだけです。

### 3. 複数のプロジェクトを同時に開発する

ワークスペースは**複数のリポジトリ**を抱えられます。ステージは*プロジェクトごとにファンアウト*でき、フロントエンド・バックエンド・SDK がそれぞれ専用のエージェントに駆動されて同時に進みます。各自が独立した **git worktree** で動くのでぶつかることはなく、差分はすべてひとつの「変更」パネルに集まります。

一部だけを選ぶこともできます。5 つのリポジトリすべてを解析して、コードを書くのはそのうち 2 つだけ —— ごく普通の設定です。

### 4. 軽量ワークフロー —— マニュアル操作

ワークフローを開始しても、最後まで一気に走ったりは**しません**。入るのは「会話モード」です。

- 上部のリボンに *N / M ステップ・現在のステージ・駆動中のエージェント* が表示されます。
- そのステージのエージェントは**目の前のチャットの中で**作業します。出力もツール呼び出しもファイル書き込みも、すべて見えます。
- 気に入らなければそのまま話しかけてください。追加の質問や修正でステージが再実行されることはありません。
- 納得したら**「次へ」**。そこで初めて引き継ぎ文が書かれ、次のエージェントに渡ります。

技術設計ステージは**実体のある markdown ドキュメント**（`forge-docs/design.md`）を書き出し、プロジェクトごとに節を分けます。要約ではなくこのドキュメントこそが、エージェント間の唯一の契約です。下流のエージェントは**全文を読んだうえで**自分の節に集中します。

ゲート付きステージは止まってあなたを待ちます：**承認**、**差し戻し**（あなたのコメントが先頭に固定され、前回の成果物がベースラインとして戻されます）、あるいは再実行を起こさずに**質問するだけ**。後になって設計の誤りに気づいたら、前のステージまで戻ってやり直せます。

### 5. ステージの合間の Hook

Hook はステージ**と**ステージの間に差し込む小さな一歩です。ステージが「エージェントに本格的な開発をさせる」ものだとすれば、Hook は「ついでに雑務を片付ける」もの。

**実行前**・**任意のステージの後**・**実行全体の後** に付けられます。最新コードの取得、設計ドキュメントの wiki への同期、lint、ボードの更新、通知の送信など。

各 Hook はワークスペースのルートで**制限付きマイクロエージェント**として動きます。与えられた Skill とツールだけを携え、現在のタスクと上流の成果物リストを受け取り、終わったら一言で報告します。人間にしか分からない壁（認証情報が足りない、どの環境を指すのか）に当たったら、勝手に推測せずあなたに直接聞きます。失敗するとパイプライン全体を**ブロック**し、再実行 / スキップ / 中止の 3 択を出します。Hook はスロットに依存しないグローバルライブラリに置かれます —— 一度書けば、どこにでも付けられます。

> **Trae**（ByteDance の TraeCode CLI）は npm では配布されていません。公式の `install.sh` が `traecli` を `~/.local/bin` に置くので、PATH に通しておいてください。ワークフロー内で無人のままファイルを編集させたい場合は `traecli config edit` で `permission_mode: bypass_permissions` を設定します。

myFlowForge は **API キーを保存せず、リクエストを中継もしません** —— 動かすのは、あなたのマシンに既にインストール・ログイン済みの CLI です。未インストールのものは設定画面でインストール方法とともに表示されます。

## 🔧 1 回の実行の形

```
     目標を伝える
            │
            ▼
  ┌─ hook ─┐        ┌─ hook ─┐                    ┌─ hook ─┐
  │ 実行前 │        │ 設計後 │                    │ 実行後 │
  └───┬────┘        └───┬────┘                    └───┬────┘
      ▼                 ▼                             ▼
 📋 要件定義 → 🎨 技術設計 → ✋ ゲート → 💻 コード開発 → 🧪 テスト → 🔍 レビュー
   (明確化)    (design.md)  あなたが判断  (ファンアウト)  (検証)    (多視点)
                     │                        │
                     │                        └─ プロジェクトごとに 1 エージェント、
                     │                           並列レーン、独立した worktree
                     └─ 実体のあるドキュメント。下流は全文を読む

 どの矢印も「次へ」を押すまで進みません。ステージは追加・削除・並べ替え・
 スキップが自由 —— 「要件定義 → コード開発」の 2 歩だけでも構いません。
```

開始方法は 3 つ、いずれも同じゲートに合流します：

1. ワークフローパネルの「開始」を押す。
2. 入力欄で `/` を打ってワークフローを選ぶ。
3. まとまった開発要件を普通の言葉で伝える。メインエージェントがそれと認識し、MCP 経由で確認ゲートを出します。単なる質問・議論・一箇所だけの修正では発動しません。

## 🧩 ほかにもこんなものが

- **ネイティブセッションのインポート** —— ローカルの Claude / Codex / Cursor / qoder の履歴を読み取り専用でスキャンし、ワークスペースとして取り込んでそのまま続けられます。
- **MCP ブリッジ** —— 内蔵の Forge MCP サーバーによりエージェントがアプリを逆に呼び出せます：`forge_ask`、`forge_propose_plan`、`forge_write_artifact`、`forge_handoff`、`forge_delegate`、`forge_read_context`、`forge_heartbeat`。MCP に対応する 8 エージェントに注入され、残りはテキスト指示にフォールバックします。
- **リアルタイムな可視性** —— 思考 / ツール呼び出し / ファイル変更 / 生の出力がすべてストリーミング。絞り込み可能なログコンソール、実行履歴、プロジェクト横断の変更証跡。
- **トークン使用量とクォータ** —— 各プロバイダの残量とリセット時刻に加え、ワークスペース × エージェント × 日 の消費量。
- **ボットブリッジ** —— スマホの **DingTalk（钉钉）** からゲートに回答し、結果を確認し、会話を始め、ワークフローを操作できます（Telegram / Feishu は接続口を用意済み）。
- **権限モード** —— 読み取り専用 · ワークスペース自動（既定）· フルアクセス。セッション単位でもステージ単位でも設定でき、各 CLI の実際のサンドボックス範囲に対応します。どのエージェントが実際に従うかは UI が明示します。
- **スラッシュコマンド・Skill・プラグイン** —— `/` でディスク上に実在するコマンドとインストール済み Skill を、エージェントごとに絞り込んで表示。
- **カスタムワークフロー** —— 手順そのものを自分で組み立てられます。名前付きワークフローをいくつでも保存でき、各ステージがエージェント・モデル・権限モード・ファンアウト形態・ゲートの有無・ドキュメント生成の要否を個別に決めます。
- **カスタムステージ** —— 自分で書いたステージのグローバルライブラリ。どのワークフローからも参照できます。
- **ファイルブラウザと差分** —— 変更マーカー付きの全画面ツリー、シンタックスハイライト付きプレビュー、差分／全文の切り替え。
- **内蔵ターミナル** —— ワークスペース直下で動く本物の pty。プロバイダごとのプロキシとタイムゾーン設定つき。
- **デスクトップペット** —— フォーカス中の画面に追従し、エージェントの動きをプレビューし、確認カードを出します。ペットマーケットを覗くことも、自分の画像を使うこともできます。
- **ウィンドウの透過とすりガラス** —— スライダー 1 本で、完全不透明から macOS ネイティブの 3 段階の vibrancy まで。デスクトップが透けて見えます。
- **パーソナライズ** —— オリジナルスキン 6 種、アクセントカラー 12 色、270 枚の内蔵壁紙ギャラリーまたは自分の画像、アプリ全体とチャット領域で独立した px 単位のフォントサイズ。ライト／ダークはそれぞれ個別にコントラスト調整済み。
- **壁紙からの自動配色** —— オンにすると配色一式が選んだ壁紙から導かれ、明暗も画像自身が決めます。壁紙が提供できるのは色相 2 つだけで、明度と彩度の段階は手で調整済みのスキンからそのまま流用 —— 情報量の多い画像でも読めない画面にはなりません。アクセントだけ自分で決めたい場合は選ぶだけで、そこだけ追従を外せます。
- **成長するペット** —— デスクトップペットが作業に応じて段階的に育ち、長いセッションのあとに目に見える何かが残ります。
- **チャット内インライン表示** —— 既定はオフ。オンにすると、エージェントが回答の途中に書いた HTML 断片が本物のカード・表・図として描画されます。`innerHTML` は一切使わず、断片を解析したうえで構成的な許可リストから組み直し、色はテーマ変数のみ許可 —— 描画結果はスキンと衝突せず追従します。

## 📥 ダウンロードとインストール

[**Releases**](https://github.com/flowForges/myFlowForge/releases) ページから最新の `.dmg` を取得してください：

| お使いの Mac | ダウンロード |
|--------------|--------------|
| Apple Silicon（M1/M2/M3/M4） | `myFlowForge-<バージョン>-arm64.dmg` |
| Intel | `myFlowForge-<バージョン>.dmg` |

> **⚠️ アプリはまだコード署名されていません。** そのため初回起動時に macOS が*「開けません」*や*「壊れています」*と表示することがあります。これは未署名アプリの正常な挙動で、ファイルが壊れているわけではありません。どちらかの方法で開いてください：
> - `/アプリケーション` 内のアプリを**右クリック** → **開く** → ダイアログで再度**開く**
> - ターミナルで一度だけ実行：`xattr -dr com.apple.quarantine /Applications/myFlowForge.app`
>
> myFlowForge は同じ Releases フィードを参照し、アプリ内で新バージョンを案内します。

## 🚀 ソースから動かす

**前提：** macOS 11 以降、Node.js ≥ 20、git、そして対応コーディング CLI が最低 1 つインストール・認証済みであること。

```bash
git clone https://github.com/flowForges/myFlowForge.git
cd myFlowForge
npm install
npm run dev          # 開発モード、レンダラーはホットリロード
```

| コマンド | 内容 |
|----------|------|
| `npm run dev` | ホットリロード付きで起動 |
| `npm test` | テスト一式を実行（Vitest） |
| `npm run typecheck` | メイン・レンダラー両方の tsconfig を型チェック |
| `npm run build` | 本番バンドルをビルド |
| `npm run dist:mac-all` | Intel と Apple Silicon 両方の `.dmg` をビルド |

成果物は `release/` に出力されます。`src/main/**` を変更した場合は **Electron の完全再起動**が必要です。ホットリロードはレンダラーしか更新しません。

## 📁 ディレクトリ構成

```
src/
├── main/              # Electron メインプロセス
│   ├── agents/        # 各 CLI アダプタ＋プロバイダ登録・検出・権限

│   ├── bot/           # ボットブリッジ（DingTalk / Telegram / Feishu トランスポート）
│   ├── plugins/       # プラグインホスト、カタログ、スケジューラ、拡張ポイント
│   ├── sessionImport/ # ネイティブセッションのスキャンとインポート
│   ├── usage/         # 各プロバイダのクォータアダプタ
│   ├── pet/           # デスクトップペットのウィンドウ
│   └── ...            # git、fs、ターミナル、更新、監視、ウィンドウ、外観
├── renderer/          # React UI（ビュー、コンポーネント、設定、テーマ、ペット）
├── preload/           # コンテキスト分離された IPC ブリッジ
└── shared/            # プロセス間で共有する型と純粋ロジック
```
